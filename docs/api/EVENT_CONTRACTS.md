# WorkPulse – Event Contract Specification

This document is the contract between the Windows desktop agent and the backend, and
between backend modules communicating over RabbitMQ and WebSockets.

## 1. Agent → Backend: activity batch

`POST /api/v1/activity/batch` · header `X-Device-Token` · `Content-Type: application/json`

```json
{
  "batchId": "7a0e4b2c-1f3d-4b8e-9c5a-2d1e6f7a8b9c",
  "deviceId": "0f3b6c0e-6d1e-4d1a-9b0e-8a5f2c3d4e5f",
  "agentVersion": "1.0.0",
  "sentAt": "2026-11-04T09:30:12.345Z",
  "clockOffsetMs": -120,
  "events": [ { "...": "see envelope" } ]
}
```

Limits: max **500 events** or **1 MB** per batch. Larger queues are drained in several batches.

### Event envelope

```json
{
  "eventId": "9f1c2b3a-4d5e-4f60-8a7b-1c2d3e4f5a6b",
  "sequence": 10231,
  "type": "FOREGROUND_APP",
  "occurredAt": "2026-11-04T09:30:05.000Z",
  "sessionId": "c1d2e3f4-5a6b-4c7d-8e9f-0a1b2c3d4e5f",
  "payload": { }
}
```

| Field | Type | Rules |
|---|---|---|
| `eventId` | UUID v4 | Generated by the agent when the event is created. Used for de-duplication. |
| `sequence` | int64 | Monotonic per device, persisted locally, never reused. Used for ordering and gap detection. |
| `type` | enum | See table below. Unknown types are stored as `UNKNOWN` and reported in `rejected`. |
| `occurredAt` | ISO-8601 UTC | Agent clock. Server stores `receivedAt` too and applies `clockOffsetMs` when deriving intervals. |
| `sessionId` | UUID | Windows logon session identifier generated by the collector at session start. |
| `payload` | object | Type-specific, validated against the schema below. |

### Event types and payloads

| Type | Emitted by | Payload |
|---|---|---|
| `AGENT_STARTED` | service | `{ "osVersion", "hostname", "agentVersion", "serviceStart": true }` |
| `AGENT_STOPPED` | service | `{ "reason": "SHUTDOWN\|UPDATE\|CRASH\|USER" }` |
| `AGENT_HEARTBEAT` | service | `{ "queueDepth", "lastSyncAt", "collectorConnected": true, "uiConnected": false }` |
| `SESSION_START` | collector | `{ "windowsUser": "DOMAIN\\user", "sessionKind": "CONSOLE\|RDP" }` |
| `SESSION_END` | collector | `{ "reason": "LOGOFF\|SHUTDOWN\|DISCONNECT\|UNKNOWN" }` |
| `SESSION_LOCK` | collector | `{}` |
| `SESSION_UNLOCK` | collector | `{}` |
| `FOREGROUND_APP` | collector | `{ "processName": "code.exe", "appName": "Visual Studio Code", "pid": 1234, "windowTitleHash": null, "durationMs": 5000 }` – one sample per sampling interval; consecutive identical samples may be coalesced by the collector by adding `durationMs`. |
| `IDLE_START` | collector | `{ "lastInputAt": "...", "thresholdSeconds": 300 }` |
| `IDLE_END` | collector | `{ "idleSeconds": 742 }` |
| `INPUT_SUMMARY` | collector | `{ "intervalSeconds": 60, "keyboardEvents": 240, "mouseEvents": 95, "mouseDistancePx": 11840, "regularityScore": 0.12 }` – aggregate counts only, never key codes or coordinates. |
| `BREAK_START` / `BREAK_END` | UI (employee-declared) | `{ "breakType": "DECLARED", "note": "Lunch" }` |
| `NETWORK_OFFLINE` / `NETWORK_ONLINE` | service | `{ "offlineSince": "..." }` |
| `POLICY_APPLIED` | service | `{ "policyId", "policyVersion" }` |
| `DEVICE_INFO` | service | `{ "cpu", "memoryMb", "osBuild", "domainJoined": true }` |

Forbidden content (rejected by the backend validator and never produced by the agent):
raw key codes, text input, clipboard data, screenshots, file paths outside the process image,
URLs with query strings, message bodies.

### Batch response

```json
{
  "success": true,
  "data": {
    "batchId": "7a0e4b2c-...",
    "accepted": 118,
    "duplicates": 2,
    "rejected": [ { "eventId": "…", "reason": "UNKNOWN_TYPE" } ],
    "serverTime": "2026-11-04T09:30:12.900Z",
    "policyVersion": 7,
    "commands": [ { "type": "REFRESH_POLICY" } ]
  }
}
```

Rules

* HTTP `200` means the batch was processed; the agent may delete every event listed in
  `accepted` and `duplicates` from the local queue. `rejected` events are moved to a
  dead-letter file and surfaced in Diagnostics – never silently discarded.
* HTTP `401 DEVICE_REVOKED` stops synchronisation and shows a revoked state in the UI.
* HTTP `409` is never returned for duplicates; de-duplication is silent and idempotent.
* HTTP `429` / `5xx` / network error → exponential back-off (2 s → 5 min, jitter), batch unchanged.

## 2. Backend → Agent: policy and commands

`GET /api/v1/agent/policy` returns the effective policy for the device's employee:

```json
{
  "policyId": "…", "version": 7,
  "samplingIntervalSeconds": 10,
  "idleThresholdSeconds": 300,
  "collectionWindows": [ { "days": [1,2,3,4,5], "from": "08:00", "to": "20:00", "tz": "Asia/Kolkata" } ],
  "collectWindowTitles": false,
  "collectInputSummary": true,
  "sensitiveAppExclusions": ["keepass.exe", "1password.exe", "outlook.exe:personal"],
  "employeeNotice": "WorkPulse records application usage and idle time during working hours…",
  "retentionDays": 180,
  "minAgentVersion": "1.0.0"
}
```

Commands delivered in heartbeat/batch responses: `REFRESH_POLICY`, `RESYNC`, `COLLECT_DIAGNOSTICS`, `UPDATE_AVAILABLE { version, url, sha256, mandatory }`, `REVOKED`.

## 3. Agent internal IPC (named pipes)

Pipe name `\\.\pipe\WorkPulse.Agent`. Newline-delimited JSON. The service is the server;
the collector and the Electron UI are clients. ACL: Authenticated Users read/write, created by
the service (LocalSystem). Every message: `{ "kind": "…", "id": "…", "ts": "…", "body": {…} }`.

| Direction | kind | Purpose |
|---|---|---|
| collector → service | `hello` | `{ "component": "collector", "sessionId", "windowsUser", "version" }` |
| collector → service | `event` | An activity event envelope (see §1) |
| service → collector | `policy` | Current effective policy |
| ui → service | `hello` | `{ "component": "ui" }` |
| ui → service | `status.get` | Request a status snapshot |
| service → ui | `status` | `{ "registered", "deviceId", "employee", "connection": "ONLINE\|OFFLINE\|REVOKED", "queueDepth", "lastSyncAt", "policyVersion", "monitoring": "ACTIVE\|PAUSED_OUTSIDE_WINDOW\|STOPPED", "currentApp", "sessionStartedAt", "version" }` |
| ui → service | `register` | `{ "accessToken", "apiBaseUrl" }` – the UI obtains a user JWT via login and hands it to the service for device registration; the service stores only the device token |
| ui → service | `break.start` / `break.end` | Employee-declared break |
| ui → service | `sync.now` | Force synchronisation |
| ui → service | `diagnostics.get` | Diagnostics bundle (queue stats, dead letters, last errors) |
| service → ui | `notification` | `{ "level", "title", "message" }` |

## 4. Backend internal: RabbitMQ

Exchange `workpulse.events` (topic). Dead-letter exchange `workpulse.dlx`. The backend declares
this topology itself on start-up (`RabbitConfig`), so the broker needs no pre-loaded definitions.

| Routing key | Producer | Consumer(s) | Payload |
|---|---|---|---|
| `activity.ingested` | `ActivityIngestionService` | `ActivityDerivationConsumer` | `{ organizationId, deviceId, employeeId, batchId, eventIds[], minOccurredAt, maxOccurredAt }` |
| `activity.derived` | derivation | live status, attendance, application usage | `{ employeeId, sessionId, intervals[] }` |
| `anomaly.candidate` | derivation | rules engine | `{ employeeId, deviceId, windowStart, windowEnd, signals }` |
| `anomaly.detected` | rules engine | notifications | `{ anomalyId, severity, employeeId }` |
| `device.health` | heartbeat | devices, websocket | `{ deviceId, health, lastSeenAt }` |
| `audit.record` | any | `AuditConsumer` | `AuditEvent` |
| `notification.created` | notifications | websocket | `Notification` |

Messages carry `messageId` (UUID) and `x-attempts`; consumers are idempotent; after 5
attempts the message is parked on `workpulse.dlq`.

